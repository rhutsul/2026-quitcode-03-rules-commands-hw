## Task B — чи бачить інструмент AGENTS.md

- Інструмент: Claude Code (десктопний застосунок, вкладка Code) · модель Opus 5 ·
  Node v24.18.0
- Як перевірив: `/context` у новій сесії, розділ **Memory files**
- Результат — `/context` показав три файли пам'яті, разом 2.2k токенів:

  | Файл | Токенів |
  |---|---|
  | `CLAUDE.md` | 282 |
  | `AGENTS.md` | 1.1k |
  | `.claude/rules/do-not-touch.md` | 854 |

  Що з цього видно:

  1. **`AGENTS.md` завантажився** — хоча Claude Code читає `CLAUDE.md`, а не
     `AGENTS.md`. Це і є результат заміни markdown-посилання на імпорт `@AGENTS.md`:
     до заміни файл у Memory files не з'являвся.
  2. **`do-not-touch.md` завантажився на старті сесії** — правило без `paths`,
     як і задумано.
  3. **`architecture.md` і `conventions.md` у Memory files відсутні** — і це
     правильно: вони прив'язані до `app/src/**/*.ts` і підтягуються лише тоді, коли
     агент працює з файлами застосунку. Тобто режими застосування обрано свідомо, а
     не «все завжди».
  4. Три команди зареєструвалися як skills: `analyze-error`, `refactor`,
     `generate-integration`.

- Контрольний запит у тій самій сесії: «не відкриваючи файлів і не запускаючи
  інструментів, перелічи правила проєкту, захищені теки й команди перед комітом».
  Агент без жодного читання файлів видав усі 7 правил, повний список захищених
  шляхів, базову лінію 18 тестів / `TOTAL: 8` і команду
  `npm test && npm run typecheck && npm run check:rules`.
- Головне спостереження: правила 2–7 агент назвав **одним рядком кожне** — саме в
  тому вигляді, як вони записані в `AGENTS.md`, — і додатково переказав `do-not-touch`
  у деталях (включно із забороною `--write-lock` і протоколом «зупинись і передай
  людині»). Деталей `architecture.md` і `conventions.md` у відповіді немає, бо ці
  файли в контекст ще не завантажені. Тобто розподіл спрацював як задумано: спільна
  база дає перелік і базову лінію в кожній сесії, детальні правила підтягуються за
  `paths` лише в роботі з `app/src/**`.
